## 1. Problem (문제)

고객이 겪는 상위 3가지 문제

1. **공지가 채팅에 묻힌다** — 일시·장소·변경 사항이 카톡방 대화에 밀려 참여자가 놓치고, 주최자는 같은 공지를 반복한다.
2. **참석 확인과 정원 관리가 수작업이다** — 댓글·이모지·투표로 참석을 세고, 취소가 나오면 대기자에게 직접 연락해야 한다.
3. **카풀과 정산 조율이 번거롭다** — 이동 수단 조율과 N분의 1 계산·입금 확인을 주최자가 혼자 떠안는다. (PRD: "주최자의 가장 큰 수작업")

### Existing Alternatives (기존 대안)

- 카카오톡 단톡방 (공지, 투표, 댓글 참석 체크)
- 엑셀/구글 스프레드시트 (참석·정산 표)
- 토스·카카오페이 정산하기 (정산 단독)
- 네이버 밴드, 모임 전용 앱 (그룹 가입이 필요하고 기능이 무겁다) **(가설)**

## 2. Customer Segments (고객 세그먼트)

타깃 고객

- **주최자**: 수영·헬스 등 운동 모임, 친구 모임을 정기적으로 운영하며 공지·참석·정산을 직접 처리하는 사람
- **참여자**: 5~30명 규모 모임의 구성원으로, 링크 하나로 응답하고 카풀·입금을 처리하고 싶은 사람

### Early Adopters (얼리어답터)

- **매주 반복되는 정기 운동 모임의 주최자** — 반복 생성(F008)과 정산(F007) 효용이 가장 크고 불편을 매주 겪는다.
- 카풀이 필요한 야외/원거리 모임을 운영하는 주최자 **(가설)**
- 이미 구글 계정을 쓰며 새 앱 설치에 거부감이 없는 20~40대 **(가설)**

---

## 3. Unique Value Proposition (고유 가치 제안)

> **"링크 하나로 공지, 참석, 카풀, 정산까지. 카톡방 수작업 없이 모임을 끝낸다."**

- 참여자는 링크 → Google 로그인 → 참석 선택, 세 단계로 끝난다.
- 주최자는 이벤트를 만들고 링크를 카톡방에 한 번만 공유하면 된다.

### High-Level Concept (상위 개념)

- **"모임 운영에 특화된 가벼운 이벤트 관리 도구"** — 그룹 가입제 없이 이벤트 링크 단위로 동작하는, 모임판 간편 이벤트 페이지 **(비유, 가설)**

---

## 4. Solution (솔루션)

상위 3가지 기능 (PRD의 MVP 핵심 기능 중 문제와 직접 대응하는 것)

| 대응 문제 | 솔루션 | PRD 기능 |
| --------- | ------ | -------- |
| 1. 공지가 묻힘 | **이벤트 상세 단일 화면**: 공지 작성·상단 고정, 공유 링크 한 개로 접근 | F002, F003 |
| 2. 참석·정원 수작업 | **참석 응답/대기 자동화**: 참석·불참 응답, 정원 초과 시 대기 등록, 취소 시 대기 1순위 자동 승급 | F004, F005 |
| 3. 카풀·정산 번거로움 | **카풀 매칭 + N분의 1 정산**: 운전자 등록·탑승 신청/수락, 출석자 기준 1인당 금액 자동 계산, 입금 표시/확인 | F006, F007 |

보조 기능: 이벤트 생성/복제(F001), 정기 모임 주간 반복 생성(F008), Google 로그인(F010), 내 이벤트 목록(F011)

## 5. Channels (채널)

고객에게 도달하는 경로

- **주최자가 직접 공유하는 이벤트 링크** — 카톡방에 공유된 링크가 곧 참여자 유입 경로 (제품 내 바이럴, F002)
- 참여자가 다른 모임의 주최자가 되는 전환 **(가설)**
- 운동 동호회·소모임 커뮤니티(수영·헬스 카페, 오픈채팅 등) 직접 소개 **(가설)**
- 후기·소개 글 등 콘텐츠 마케팅 **(가설)**

## 6. Revenue Streams (수익 흐름)

> PRD에 수익 모델이 없습니다. MVP는 검증이 우선이며 아래는 모두 **(가설)** 입니다.

- **MVP 단계**: 무료 제공 (결제 연동은 MVP 제외 범위)
- **프리미엄 구독**: 반복 이벤트 수 확대, 대규모 정원, 이벤트 기록 보관 기간 연장 등 **(가설)**
- **주최자 전용 유료 기능**: 알림(카카오톡/푸시), 회비 장부 등 PRD의 "MVP 이후 기능" 중 유료화 후보 **(가설)**
- 지표: 유료 전환율, LTV, 매출총이익률은 유료 모델 도입 시 측정

## 7. Cost Structure (비용 구조)

- **호스팅/인프라**: Vercel, Supabase (인증, PostgreSQL) — 초기에는 무료/저가 플랜 범위 **(가설)**
- **개발 인력**: 1인 개발 기준 개발·운영 시간 (가장 큰 비용)
- **고객 확보 비용**: 링크 공유 기반이라 낮게 시작, 커뮤니티 홍보 시간 비용 **(가설)**
- **서비스 계정/도메인**: Google OAuth 설정, 도메인 비용
- **향후 비용 (MVP 이후)**: 알림 발송, 결제 연동 수수료

## 8. Key Metrics (핵심 지표)

측정할 핵심 활동

| 단계 | 지표 | 의미 |
| ---- | ---- | ---- |
| 획득 | 이벤트 링크당 방문 → 로그인 → 응답 전환율 | 링크 참여 흐름의 마찰 |
| 활성화 | 이벤트 생성 후 7일 내 응답 3건 이상 비율 **(가설)** | 주최자가 실제 가치를 얻은 비율 |
| 사용 깊이 | 이벤트당 공지·카풀·정산 기능 사용률 | 단순 참석 체크를 넘어선 사용 |
| 유지 | 주최자의 재생성/복제/반복 이벤트 비율, 4주 재방문 | 정기 모임 정착 여부 |
| 바이럴 | 참여자 중 이벤트를 새로 만든 비율 | 참여자 → 주최자 전환 |
| 정산 | 정산 생성 이벤트 중 입금 확인 완료율 | 핵심 차별 기능의 완결성 |

> North Star 후보: **"정산까지 완료된 이벤트 수"** (주최자 수작업 제거 가치를 가장 잘 반영) **(가설)**

## 9. Unfair Advantage (경쟁 우위)

쉽게 복사하거나 살 수 없는 것

> 초기 MVP 단계에서 확고한 방어 요소는 아직 없습니다. 아래는 **키워야 할 방향**입니다. **(가설)**

- **참석 + 카풀 + 정산이 하나로 묶인 모임 특화 워크플로** — 단일 기능 앱(투표, 정산)보다 전환 비용이 높다.
- **링크 기반 진입으로 가입 장벽이 낮은 구조** — 그룹 가입제 앱 대비 참여 마찰이 적다.
- **정기 모임 이력 데이터** — 복제·반복 이벤트와 정산 기록이 쌓일수록 다른 도구로 옮기기 어렵다.
- 창업자가 직접 모임을 운영하는 사용자라는 도메인 이해 **(확인 필요)**

---

## 검증 우선순위 (가장 위험한 가정)

1. **주최자가 카톡방 대신 링크 기반 서비스로 옮겨 올 만큼 불편을 느끼는가?** → 정기 모임 주최자 5~10명 인터뷰 및 시범 운영
2. **참여자가 Google 로그인을 거쳐도 응답하는가?** (로그인 장벽) → 링크 → 응답 전환율 측정 (F002)
3. **카풀과 정산 기능이 실제로 쓰이는가?** → 이벤트당 기능별 사용률 확인
4. **이 문제에 지불 의사가 있는가?** → 수익 모델은 MVP 사용 데이터를 본 뒤 검증
