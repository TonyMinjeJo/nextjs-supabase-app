# 모임 이벤트 관리 웹 개발 로드맵

주최자가 공지, 참석, 카풀, 정산을 링크 하나로 처리하는 모임 이벤트 관리 MVP

## 개요

모임 이벤트 관리 웹은 수영·헬스 등 정기 모임과 친구 모임의 주최자·참여자(5~30명)를 위한 올인원 이벤트 관리 서비스로 다음 기능을 제공합니다:

- **이벤트 + 공지 (F001, F003, F008)**: 이벤트 생성/복제, 주간 반복 생성, 공지 작성과 고정
- **공유 링크 참여 + 참석/출석 (F002, F004, F005)**: 링크로 진입해 Google 로그인 후 참석 응답, 정원 초과 시 대기 및 자동 승급, 출석 체크
- **카풀 + 정산 (F006, F007)**: 운전자/탑승자 매칭, 출석자 기준 N분의 1 계산과 입금 체크
- **인증 + 내 이벤트 (F010, F011)**: Google 로그인(구현됨), 내 이벤트 목록

> 기준 문서: `docs/PRD.md`. 소스는 `src/`가 아닌 저장소 루트(`app/`, `components/`, `lib/`)에 있습니다.
> 기존 자산: Supabase Auth, Google OAuth 로그인/콜백, `proxy.ts` 세션 갱신, `app/protected` 예제 영역.

## 개발 워크플로우

1. **작업 계획**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- 새로운 작업을 포함하도록 `ROADMAP.md` 업데이트
- 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- `/tasks` 디렉토리에 새 작업 파일 생성
- 명명 형식: `XXX-description.md` (예: `001-setup.md`)
- 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
- API/비즈니스 로직 작업 시 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 시나리오)
- 테스트 체크리스트는 정상·예외·경계·회귀 시나리오를 모두 포함 (정상 1+, 예외 2+, 경계 1+, 회귀 1+, 네트워크 확인 1+, UI 포함 시 모바일 1+)
- 예시를 위해 `/tasks` 디렉토리의 마지막 완료된 작업을 참조. 새 작업 문서는 빈 박스 상태로 시작

3. **작업 구현**

- 작업 파일의 명세서를 따름
- API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트 수행 필수
- 구현 완료 후 ① 범위 분석 → ② 시나리오 설계 → ③ 환경 준비 → ④ Playwright MCP 실행 → ⑤ 결과 검증 → ⑥ 기록 및 완료 판정 순서로 수행
- 실패 시 원인을 구현 버그 / 시나리오 오류 / 환경 문제로 분류, 구현 버그는 수정 후 해당 시나리오부터 재실행
- 정상·예외·경계 시나리오가 모두 통과해야 완료. 이후 `npm run check-all` → `npm run build` 실행
- 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**

- 로드맵에서 완료된 작업을 ✅로 표시

## 개발 단계

### Phase 1: 애플리케이션 골격 구축

- **Task 001: 라우트 구조 및 레이아웃 골격 구성** - 우선순위
  - 라우트 빈 페이지 생성: 내 이벤트, 이벤트 생성, 이벤트 초대(`/e/[code]`), 이벤트 상세(`/events/[id]`), 이벤트 관리(`/events/[id]/manage`)
  - 홈과 로그인은 기존 `app/page.tsx`, `app/auth/login`을 재사용하고 시작 버튼 동선만 정리
  - 로그인 후 공통 헤더 골격 (내 이벤트, 이벤트 만들기, 로그아웃)
  - `proxy.ts`/`updateSession`의 비로그인 허용 경로 정책 확정 (`/e/*` 처리 방식: 공개 요약 + 로그인 유도)
  - 로그인 후 복귀 경로(`next`) 흐름 점검 (기존 confirm 라우트의 경로 검증 로직 재사용)
  - 이벤트 상세 탭 골격 (공지 / 참석자 / 카풀 / 정산)

- **Task 002: 타입 정의 및 인터페이스 설계**
  - PRD 데이터 모델 기반 TypeScript 도메인 타입 초안 (`lib/types/`): Event, Participation, Announcement, CarpoolRide, CarpoolPassenger, Expense, SettlementShare
  - 상태 값 유니온 타입 정의 (going/not_going/waitlist, pending/accepted/rejected)
  - Zod 입력 검증 스키마 초안 (이벤트 생성, 비용 입력)
  - 화면 컴포넌트와 더미 데이터가 공유할 Props/뷰 모델 타입 정의
  - 범위 제외: DB 스키마·인덱스·RLS 설계와 Supabase 연동은 Phase 1~2에서 하지 않으며, Task 005-1 UI 검토 후 Task 006에서 진행

> Phase 1~2는 Supabase DB를 사용하지 않고 `lib/types/` 타입과 `lib/mocks/` 더미 데이터만으로 진행합니다. 기존 Supabase Auth(Google 로그인)는 그대로 유지합니다.

### Phase 2: UI/UX 완성 (더미 데이터 활용)

- **Task 003: 공통 컴포넌트 라이브러리 구현**
  - shadcn/ui 추가 설치: Tabs, Dialog, Badge, Checkbox, Select, Calendar/DatePicker, Textarea, Toast
  - 이벤트 카드, 참석 상태 뱃지, 인원 게이지(현재/정원), 빈 상태 컴포넌트
  - 더미 데이터 모듈 (`lib/mocks/`) 작성
  - 모바일 우선 레이아웃 기준 확립 (공유 링크는 주로 폰에서 열림)

- **Task 004: 내 이벤트·이벤트 생성 UI**
  - 내 이벤트: 주최/참여 구분, 예정/지난 구분, 참석 상태 뱃지
  - 이벤트 생성 폼 (react-hook-form + Zod): 제목/설명/일시/장소/정원/마감
  - 주간 반복 설정 UI (요일, 종료일)과 복제 진입 UI
  - 공유 링크 복사 버튼 UI

- **Task 005: 이벤트 초대·상세·관리 UI**
  - 이벤트 초대: 요약, 참석/불참 버튼, 정원 초과 시 대기 안내, 잘못된 링크 화면
  - 이벤트 상세 4개 탭 UI (공지, 참석자, 카풀, 정산) — 주최자/참여자 뷰 분기
  - 이벤트 관리: 출석 체크리스트, 비용 입력, 1인당 금액/입금 상태 표
  - 모든 사용자 플로우를 더미 데이터로 끝까지 체험 가능하도록 연결

- **Task 005-1: UI 검토 및 보완**
  - 더미 데이터로 주최자/참여자 전체 플로우 직접 체험 (생성 → 링크 공유 → 참석 → 카풀 → 출석 → 정산), 데스크톱·모바일 뷰포트 모두 확인
  - 화면/흐름/입력 필드 보완 사항 목록화 (누락 필드, 불필요 단계, 상태 표시 혼선 등) 및 우선순위 결정
  - 결정된 보완 사항을 Task 003~005 UI와 `lib/mocks/` 더미 데이터에 반영
  - 보완 결과를 `lib/types/` 도메인 타입·Zod 스키마와 `docs/PRD.md` 데이터 모델에 반영하여 확정
  - 게이트: 이 Task가 완료되어 타입과 PRD 데이터 모델이 확정되어야 Phase 3(Task 006)로 진행

### Phase 3: 핵심 기능 구현

- **Task 006: Supabase 스키마·RLS 설계·적용 및 타입 생성** - 우선순위
  - Task 005-1에서 확정된 타입/PRD 데이터 모델 기준으로 DB 스키마(테이블·관계·인덱스)와 RLS 정책(조회/쓰기 주체별) 설계
  - Supabase MCP로 마이그레이션 적용 (profiles, events, event_series, participations, announcements, carpool_rides, carpool_passengers, expenses, settlement_shares)
  - 모든 테이블 RLS 활성화, 정책 적용 (주최자 쓰기, 참여자 본인 행 쓰기, 참여자만 하위 데이터 조회)
  - 로그인 시 profiles 자동 생성 트리거 (Google 이름/아바타)
  - `generate_typescript_types`로 DB 타입 생성 후 Task 005-1에서 확정된 도메인 타입(`lib/types/`)과 정합화
  - `get_advisors`(보안/성능) 점검 및 경고 해소

- **Task 007: 이벤트 생성·조회·공유 링크 구현 (F001, F002, F011)**
  - 이벤트 생성/수정/복제 서버 액션 (서버 검증 + 주최자 권한)
  - `share_code` 발급(추측 어려운 난수)과 `/e/[code]` 조회
  - 내 이벤트 목록 실데이터 연동 (더미 교체)
  - Cache Components 규칙: 동적 데이터는 Suspense 내부
  - Playwright MCP 테스트 (아래 체크리스트)

- **Task 008: 참석 응답·대기 승급·출석 구현 (F004, F005)**
  - 참석/불참 응답 서버 액션, 정원 초과 시 대기 등록
  - 참석 취소 시 대기 1순위 자동 승급 (DB 함수 또는 트랜잭션으로 동시성 보장)
  - 신청 마감 이후 응답 차단
  - 출석 체크 (주최자 전용) 및 인원 요약
  - Playwright MCP 테스트 (아래 체크리스트)

- **Task 009: 공지 구현 (F003)**
  - 공지 작성/삭제/상단 고정 (주최자 전용), 최신순 + 고정 우선 정렬
  - 참여자 조회 권한 검증
  - Playwright MCP 테스트 (아래 체크리스트)

  - Playwright MCP 테스트: 금액은 입력값으로 직접 계산한 값과 대조

- **Task 012: 정기 모임 반복 생성 구현 (F008)**

- **Task 012-1: 핵심 기능 통합 테스트**
  - Playwright MCP로 전체 플로우 E2E: 주최자 생성 → 링크 공유 → 참여자 로그인·참석 → 카풀 → 출석 → 정산 → 입금 확인
  - 정원 초과·대기 승급·마감 후 응답 등 엣지 케이스 재검증
  - 두 계정(주최자/참여자) 권한 분리 확인 (RLS 우회 시도 포함)
  - 콘솔 에러·네트워크 실패 없음 확인, 모바일 뷰포트 반복
