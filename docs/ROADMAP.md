## 개요

수영·헬스 등 정기 모임과 친구 모임의 주최자·참여자(5~30명)를 위한 이벤트 관리 서비스입니다.

| 영역             | 기능                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| 이벤트 + 공지    | 이벤트 생성/복제/취소, 공지 작성과 고정 (F001, F003)                                  |
| 공유 링크 + 참석 | 링크 진입 → Google 또는 이메일 로그인 → 참석 응답, 대기·자동 승급, 출석 체크 (F002, F004, F005) |
| 인증 + 내 이벤트 | Google·이메일 로그인, 내 이벤트 목록 (F010, F011)                                     |

## 개발 워크플로우

1. **작업 계획** — 코드베이스 현재 상태를 파악하고, 새 작업을 이 문서에 추가합니다. 우선순위 작업은 마지막 완료 작업 바로 다음에 넣습니다.
2. **작업 생성** — 고수준 명세, 관련 파일, 수락 기준, 구현 단계를 정리합니다.
   - API·비즈니스 로직 작업에는 "테스트 체크리스트"(Playwright MCP 시나리오)가 필수입니다.
   - 시나리오 구성: 정상 1+, 예외 2+, 경계 1+, 회귀 1+, 네트워크 확인 1+, UI가 있으면 모바일 1+. 새 작업의 체크박스는 비운 채로 시작합니다.
3. **작업 구현** — 구현 후 ① 범위 분석 → ② 시나리오 설계 → ③ 환경 준비 → ④ Playwright 실행 → ⑤ 결과 검증 → ⑥ 기록·완료 판정 순서로 진행합니다.
   - 실패하면 원인을 **구현 버그 / 시나리오 오류 / 환경 문제**로 나눕니다. 구현 버그는 고친 뒤 해당 시나리오부터 다시 실행합니다.
   - 정상·예외·경계가 모두 통과해야 완료입니다. 그 뒤 `npm run check-all` → `npm run build`를 실행합니다.
   - 각 단계가 끝나면 멈추고 추가 지시를 기다립니다.
4. **로드맵 업데이트** — 완료한 작업은 ✅로 표시하고, 긴 결과·검증 메모는 아래 "작업 기록"에 적습니다. 본문에는 한두 줄 요약만 남깁니다.

> Phase 1~2는 Supabase DB 없이 `lib/types/` 타입과 `lib/mocks/` 더미 데이터로 진행했고, 기존 Supabase Auth는 그대로 유지했습니다.

**이벤트 취소 규칙** (삭제는 "취소됨" 상태 전환으로 구현)

- 주최자만 취소할 수 있습니다. 이미 취소했으면 `already_canceled`, 취소된 이벤트에는 참석 응답·출석을 거부합니다 (`event_canceled`).
- 삭제는 취소된 이벤트만 가능하며(`delete_event` RPC), 주최자의 직접 `DELETE`와 `canceled_at` 직접 `UPDATE`는 권한을 회수했습니다.

### 시험 환경 메모 (공통)

- **Task 010에서 쓴 방식 (이메일 계정만으로 여러 사용자 시험)**: 이메일 인증 메일을 받을 수 없을 때는 승인을 받은 뒤 SQL로 `auth.users`(이메일 인증 완료, `crypt()`로 비밀번호 해시)와 `auth.identities`를 직접 만들면 `signInWithPassword`로 로그인됩니다. 토큰 컬럼(`confirmation_token`, `recovery_token`, `email_change_token_new`, `email_change`)은 `NULL`이 아닌 빈 문자열이어야 합니다. 계정마다 `browser_tabs`의 `isolatedContext`를 따로 주면 쿠키가 분리됩니다. 시험 계정은 `@example.test` 도메인과 `[T010]` 제목 접두어로 구분하고, 끝나면 이벤트 → 참석·공지 → 프로필 → `auth.identities` → `auth.users` 순서로 지웁니다.
- **RLS 우회 시험**: `execute_sql`의 `do $$ ... $$` 안에서 `set_config('request.jwt.claims', ...)`와 `set local role authenticated`(또는 `anon`)로 사용자를 흉내 내고, 마지막에 `raise exception`으로 결과를 돌려주면 항상 롤백되어 데이터가 남지 않습니다.
- **스크린샷 저장 위치**: Playwright MCP는 프로젝트 폴더(`.playwright-mcp/`) 밖에는 파일을 저장하지 못합니다.

- **두 계정이 필요한 시험**: Google 계정(`minjetony@gmail.com`, 주최자·admin)과 이메일 계정(`minjetony@naver.com`, 참여자). Playwright 브라우저 컨텍스트를 2개 열어 각각 로그인하고, 쿠키의 세션 토큰으로 PostgREST를 직접 호출하면 두 계정의 동시 요청(`Promise.all`)도 만들 수 있습니다. 한쪽 세션을 정리할 때는 로그아웃 버튼 대신 컨텍스트 쿠키만 지웁니다(전역 로그아웃으로 다른 세션이 끊길 수 있음).
- **계정 역할**: 비멤버·비주최자 시험을 위해 `minjetony@naver.com`의 `profiles.role`을 `admin`에서 `user`로 바꿨고 되돌리지 않았습니다. `/admin` 화면을 이 계정으로 확인하려면 다시 `admin`으로 올려야 합니다.
