# 모임 이벤트 관리 웹 MVP PRD

## 🎯 핵심 정보

**목적**: 모임 주최자가 공지, 참석 확인, 카풀, 정산을 카톡방 수작업 없이 링크 하나로 처리하게 한다.
**사용자**: 수영·헬스 등 정기 모임과 친구 모임을 운영하는 주최자, 그리고 5~30명 규모의 참여자.

## 🚶 사용자 여정

```
[주최자]
1. 홈
   ↓ Google로 시작하기
2. 로그인
   ↓ 로그인 성공
3. 내 이벤트
   ↓ 이벤트 만들기
4. 이벤트 생성 (반복 옵션 선택 가능)
   ↓ 생성 완료 → 공유 링크 복사 → 카톡방에 공유
5. 이벤트 상세 (공지 / 참석자 / 카풀 / 정산)
   ↓ 이벤트 종료 후
6. 이벤트 관리 (출석 체크 → 비용 입력 → 입금 확인)

[참여자]
1. 공유 링크로 이벤트 초대 진입
   ↓
   [비로그인] → 로그인 → 이벤트 초대로 복귀
   [로그인]   → 참석 / 불참 선택
   ↓
   [정원 여유] → 참석 확정 → 이벤트 상세
   [정원 초과] → 대기 등록 → 이벤트 상세
2. 이벤트 상세에서 카풀 신청/등록, 입금 완료 표시
```

## 🗄️ 데이터 모델

> **시각 처리 규칙:** 서비스는 한국 시간(KST, +09:00)을 기준으로 합니다. 폼의 `datetime-local` 값(시간대 없음)은 `lib/datetime.ts`의 `toKstIso()`로 ISO 8601(`+09:00`)로 변환해 저장하고, 화면 표시는 `Asia/Seoul`로 고정합니다. (Task 005-1에서 확정)

### events (이벤트)

| 필드           | 설명               | 타입/관계             |
| -------------- | ------------------ | --------------------- |
| id             | 고유 식별자        | UUID                  |
| host_id        | 주최자             | → profiles.id         |
| series_id      | 반복 규칙 (선택)   | → event_series.id     |
| title / starts_at / location | 기본 정보 | text / timestamp / text |
| capacity / rsvp_deadline     | 정원 / 신청 마감 | int / timestamp  |
| share_code     | 공유 링크 코드     | text (unique)         |
| transfer_account | 송금 안내 계좌 (선택) | text. 주최자·참여자·admin만 조회, 공개 초대 RPC는 반환하지 않음 |
| canceled_at    | 취소 시각 (null이면 진행 중) | timestamp. `cancel_event` RPC로만 설정, 직접 UPDATE 불가 |

**이벤트 취소·삭제 규칙** (쓰기는 `cancel_event`·`delete_event` RPC로만 수행, `events`의 직접 `DELETE`·`canceled_at` `UPDATE`는 권한을 회수)

- 취소: 주최자만 할 수 있다(`not_host`). 이벤트는 삭제되지 않고 "취소됨" 상태로 남는다. 이미 취소했으면 `already_canceled`로 거부한다.
- 차단: 비용 항목(`expenses`)이나 정산 분담(`settlement_shares`)이 하나라도 있으면 취소할 수 없다(`settlement_in_progress`).
- 취소 후: 참석 응답과 출석 체크를 거부한다(`event_canceled`). 수정·관리 화면은 숨기고, 공개 초대 화면은 "취소된 이벤트예요. 더 이상 응답할 수 없어요."를 보여 준다. 취소는 되돌릴 수 없다.
- 삭제: 취소된 이벤트만 주최자가 삭제할 수 있다. 비용·정산이 있으면 삭제도 차단하며, 참석·공지·카풀 등 연결 데이터는 함께 삭제된다.

| created_at | 응답 시각 (대기 순번 기준: 먼저 응답한 순) | timestamp |

**참석 규칙** (쓰기는 `respond_to_event`·`set_attendance` RPC로만 수행)

- 응답 대상: 호스트를 포함한 모든 로그인 사용자가 같은 규칙으로 직접 응답한다.
- 정원: 참석 요청 시 정원에 여유가 있으면 `going`, 가득 차면 `waitlist`로 등록한다. 대기 순번은 `created_at`이 이른 순이다.
- 마감: `rsvp_deadline` 이후의 응답은 `rsvp_closed`로 거부한다. 이벤트 시작 시각 이후에는 별도로 막지 않는다.
- 승급: `going` 참석자가 불참으로 바꾸면 대기 1순위가 자동으로 `going`이 된다. 정원이 늘어나면 늘어난 자리만큼 대기자를 순서대로 승급한다(DB 트리거).
- 정원 감소: 이미 `going`인 참석자는 강등하지 않는다(정원보다 참석자가 많을 수 있다).
- 출석: 호스트만 `going` 참석자의 `attended`를 바꿀 수 있다.

### announcements (공지)

| 필드      | 설명        | 타입/관계     |
| --------- | ----------- | ------------- |
| id        | 고유 식별자 | UUID          |
| event_id  | 이벤트      | → events.id   |
| author_id | 작성자 (항상 주최자, 서버가 세션에서 채움) | → profiles.id |
| body      | 공지 내용   | text (1~1000자, 서버 검증) |
| pinned    | 상단 고정   | boolean       |
| created_at | 작성 시각 (최신순 정렬 기준) | timestamp |

**공지 규칙** (쓰기는 서버 액션이 RLS 아래 테이블을 직접 호출, 별도 RPC 없음)

- 작성·삭제·상단 고정은 주최자만 할 수 있다. 참여자 화면에는 입력창과 버튼을 보이지 않고, 서버(RLS)도 거부한다.
- 정렬은 고정 공지 우선, 그다음 최신순이다. 고정 개수에는 제한이 없다.
- 읽기 권한은 주최자와 응답한 적 있는 참여자(참석·대기·불참 상태 무관)다. 응답한 적 없는 사용자는 조회할 수 없다.
- 본문은 공백만으로는 등록할 수 없고 최대 1000자다. 길이 제한은 서버 검증(Zod)에만 있고 DB에는 빈 문자열 방지 CHECK만 있다.
- 수정 기능은 없다(작성·삭제·고정만). 오타는 삭제 후 다시 등록한다.
- 취소된 이벤트는 모두에게 읽기 전용이다. 주최자 화면에서도 입력창과 고정·삭제 버튼을 숨기고, 서버 액션이 작성·고정·삭제를 거부한다. 이 차단은 서버 액션에만 있고 DB 정책은 막지 않는다.
- 이벤트가 삭제되면 공지도 함께 삭제된다(FK cascade). 공지 알림(푸시·이메일)은 MVP 범위 밖이다.
